# Piano Practice

Офлайн-тренажёр для самостоятельных занятий за пианино. **Learning**: 16 недель, 48 уроков, 3 × 40 минут в неделю. **Practice**: независимые Degree, Chord, Style, Fill & Run и Scale & Pattern тренажёры. Интерфейс на русском. Сервер, регистрация и MIDI не нужны.

Проект находится **в корне `D:\petproject\piano-practice`**. Папка `piano-practice-codex-blue` содержит только исходное ТЗ и макеты.

Practice включает 36 типов аккордов, 95 гармонических прогрессий, все 12 тональностей, адаптацию к сложным заданиям, подсказки с воспроизведением, отдельные аудиоканалы и локальные голоса EN/PL. Настройки, сессии и история сохраняются отдельно от Learning. Архитектура, музыкальные соглашения, офлайн-ресурсы и команды проверки — в [docs/PRACTICE.md](docs/PRACTICE.md).

## Запуск

Node.js 22.12+ (или 24), npm.

```sh
npm ci
npm run dev
```

Открой URL `/piano-practice/`, который напечатает Vite. Для проверки настоящего офлайн-режима нужна production-сборка:

```sh
npm run build
npm run preview
```

В development service worker отключён. В production он кэширует приложение, определения всех уроков, иконки, девять локальных MP3 и 18 голосовых WAV EN/PL. Надпись «Готово к занятиям офлайн» появляется только после проверки наличия пианино и голосовых файлов в Cache Storage. Первый запуск требует подключения. На iPhone установка и service worker требуют HTTPS; обычный LAN URL по HTTP подходит только для визуального просмотра.

## Что работает

- Последовательный курс, просмотр будущих уроков, переход к любому шагу, отдельные повторные попытки без потери достижений.
- Гаммы, аккорды, последовательности и прогрессии; точные MIDI-высоты, музыкальное написание ступеней, локальный скролл клавиатуры, аппликатура при наличии.
- Tone.js, Salamander Grand Piano и автоматический PolySynth при недоступных сэмплах. Play/Pause/Stop, 40–180 BPM, loop, mute, громкость, независимый метроном с четвертями/восьмыми/триолями/шестнадцатыми.
- Музыкальные примеры для ранов, филлов, хроматики, окружений и импровизации во всех 48 уроках: 25 авторских фраз, минимум два контекста в каждом соответствующем упражнении. Аккорды левой руки удерживаются под мелодией правой; целевая нота совпадает со сменой гармонии.
- Таймер по монотонным timestamps: пауза в фоне, checkpoint каждые 5 секунд, восстановление в паузе, Wake Lock при поддержке. Сброс отсчёта не удаляет фактическое время практики. Истечение времени не завершает шаг.
- Повторения через 1/3/7/14/30 дней от первого изучения. Состав review фиксируется в начале попытки; максимум 10 минут, до четырёх заданий. После курса доступно дальнейшее повторение. Mastery требует успешной базовой проверки и всей цепочки до 30-го дня.
- IndexedDB/Dexie, миграция схемы, проверяемый JSON-экспорт/импорт с подтверждением полной атомарной замены. Неизвестные ID сохраняются и сообщаются при импорте.
- Тёмная, светлая и системная темы; safe-area; HashRouter; обновление SW только по согласию вне активного занятия.

## Музыкальные примеры

В подходящем упражнении открой «Музыкальные примеры», выбери фразу и тональность. Карточка показывает аккорды, мелодию со ступенями и длительностями, обе руки на клавиатуре и функцию целевой ноты. Нажимай на аккорды, ноты или стрелки, чтобы разобрать фразу по событиям без звука. Play запускает фразу целиком; Pause сохраняет точную позицию, Stop возвращает к началу. Есть цикл, ползунок темпа, замедление и возврат к рекомендуемому BPM. План разучивания находится под плеером.

Примеры встроены в 334 упражнения текущего курса (816 размещений с учётом тональностей и закрепления). Сложность растёт от короткого ответа на двух аккордах до нескольких фраз и шестнадцатых в ii–V–I и четырёхаккордовых прогрессиях. Все данные и сэмплы доступны офлайн после первого кэширования.

`MusicalExample` — необязательное расширение `Exercise` и `Step`. События задаются в долях с длительностью, рукой и ролью; аккорды и целевые ноты имеют собственные позиции. Чистые функции в `src/core/music/examples.ts` транспонируют весь контекст и преобразуют его в общий `PlaybackPlan`. Плееры используют один `AudioControls` и существующий аудиосервис; для двух рук выделены независимые голоса, чтобы отпускание ноты мелодии не обрывало ту же высоту в удерживаемом аккорде. ID программы, уроков и шагов сохранены; старые попытки и резервные копии совместимы.

## Структура

`src/core` — чистые музыкальный, уроковый и review-движки и типы. `src/programs` — декларативная программа. `src/database` — Dexie, репозиторий и резервные копии. `src/audio` — адаптер Tone.js и расписание. `src/features` — таймер и PWA. `src/components` — клавиатура и универсальный просмотрщик. `src/pages` — экраны. `src/stores` — гидратация и runtime-состояние.

Для второй программы добавь объект `Program` и зарегистрируй его в `src/programs/registry.ts`. Движки и маршруты используют стабильные ID и не требуют изменений. Независимость прогресса второй программы проверяется интеграционным тестом.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Тесты проверяют все 12 корней, альтерации и октавы, P5/P9/P10, обращения, расписание аудио, отмену подсветки, таймер, миграцию, возобновление, повторы, завершение 48 уроков, атомарный импорт и второй курс. Результаты браузерной проверки и оставшаяся приёмка на реальном устройстве — в `docs/VERIFICATION.md`.

## GitHub Pages

Workflow `.github/workflows/deploy.yml`: `npm ci` → typecheck → lint → tests → build → проверка WAV → E2E Chromium/WebKit → Pages artifact → deploy → проверка опубликованных JS/CSS. Он срабатывает при push в `main`/`master` или ручном запуске.

Настройки репозитория для публикации:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**. Режим «Deploy from a branch» опубликует исходный `index.html` с TypeScript вместо сборки и приведёт к пустому экрану.
2. **Settings → Environments → github-pages → Deployment branches and tags**: разрешить используемую ветку `master` (либо `main`, если публикация идёт из неё). Остальные правила защиты окружения сохраняются.
3. В **Actions → Deploy Piano Practice** запустить workflow для нужной ветки. Успешными должны быть оба задания: `build` и `deploy`, включая проверку опубликованных файлов.

Базовый путь настроен на `/piano-practice/`, manifest использует относительные `start_url` и `scope`. Публикуется только `dist/`. Проверить конкретный сайт вручную можно командой:

```sh
node scripts/verify-deployment.mjs https://oskarvitko.github.io/piano-practice/
```
